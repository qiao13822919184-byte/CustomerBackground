# CustomerBackground · 团队客户背调工作台

面向海外 B2B 团队的广告主建档、客户身份研究、开发分级和建联草稿系统。代码可放在 GitHub；实际应用部署到阿里云等服务器。未使用 OpenAI Sites。

## 功能

- 管理员创建账号，团队按工作区共享档案、线索、报告和操作记录，关闭公开注册。
- 每账号可分配独立 API URL、加密密钥和模型；实际模型、工具往返和结构化分析测试通过后才允许保存分配和启用账号。
- 客户信息自动保存、约3秒刷新共享状态、并发修改冲突提示、历史版本。
- 支持文本和客户端解析的 MD/TXT/CSV/XLSX/DOCX/PDF，图片交给支持视觉的模型；扫描PDF需要转换为图片。原文件内容作为资料，不作为指令。
- 可复用广告主MD档案；新增材料增量分析。客户原字段和查证来源分开保存。
- 身份匹配1–3级、开发必要度1–5级，等级越高越匹配/优先；话术按证据准入。
- 后台任务在关闭浏览器后继续；服务器重启时运行中任务标记中断，防止无提示重复计费。排队任务自动恢复。
- 通用 Skill 位于 `skills/overseas-lead-research`，不包含任何真实客户或广告主资料。

## 单独复用 Skill

[海外 B2B 客户背调 Skill](skills/overseas-lead-research/SKILL.md) 可独立安装到 Codex 的技能目录。安装后直接调用：

```text
请用 $overseas-lead-research，根据我上传的广告主资料和客户表单完成背调、匹配分级、建联草稿，并保存可复用 MD 档案。
```

以后提供已保存的广告主档案和新增客户表单即可继续；客户有新回复时，同时提供其客户档案。默认文件保存在当前项目的 `customer-research/`，不提交 GitHub。Skill 包含档案模板、身份核验及评分规则；文件解析和联网依赖运行环境，团队账号与共享数据库仍由应用提供。

## 本地启动

需要 Node.js 24 或更新受支持版本。

```sh
npm ci
cp .env.example .env
# 在 .env 配置真实API；本地测试删去示例APP_ORIGIN，或设为实际访问地址。
npm run build
npm start
```

浏览器访问 `http://127.0.0.1:8787`。首次初始化令牌自动写入 `.local/data/server-secrets.json`，只由服务器管理者读取；没有公开默认管理员密码。初始化后令牌不能创建第二个管理员。

首次创建团队成员时账号停用。在“团队协作 → 模型配置”选择继承默认配置或独立密钥，完成实际测试后保存，再启用账号。模型接口与密钥从不写入浏览器存储；空白密钥输入代表沿用已有值。更换API域名必须同时提供新密钥。更改继承配置后，受影响账号需重新测试。

## 阿里云部署

完整步骤见 [部署说明](deploy/ALIYUN.md)。一台Linux服务器即可运行 Node 应用和 SQLite 数据库，无需额外购买云数据库。它适用于小团队单实例部署；扩大到多实例前需迁移数据库及任务锁。数据库、密钥与上传材料位于持久化数据目录，不能放进GitHub。

## 实际研究能力与边界

运行时通过真实 `search_web` / `read_page` 工具获取公开证据，支持可选Brave Search。公开搜索受地区、限流和网页可访问性影响；失败会记录，不会写成已核验。当前网页读取能力不等于所有Google Maps动态内容、企业登记和付费数据库都能自动访问；这些未覆盖部分会在报告标明，不能将整个网站存在当成联系人已绑定。

API中转服务提供模型；搜索与抓取由本应用执行。工具调用或结构化分析不兼容的模型会在分配测试中失败。生成结果需按证据审核；系统不发送客户消息。

## 验证与发布

```sh
npm run typecheck
npm test
npm run build
```

GitHub Actions自动构建验证；服务器配置完成后可手动运行“Deploy to configured server”。上线前配置真实 `APP_ORIGIN` 与HTTPS，确认持久化卷、备份及海外站点可访问性。密钥和管理员初始化资料从不提交仓库。
